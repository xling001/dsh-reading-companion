## 现行约定

### 定位（所有取舍都要服从它）
1. **尽可能用 DSH 现成的功能与工具**（能宿主侧现算的，就不让客户端上报）。
2. **主服务场景：中长篇小说。**（⚠️ 这是**投入排序**，**不是给模型的指令** —— 每条提示词都必须对**任何文本**成立：读文献的人不该在提示词里看到一句"小说优先"。读者 2026-10-02 纠正过一次，见修订史 §569。）
3. **导出文件的质量（`notes.md` / `background.md`）是价值主轴。**
4. **背景文件是"记忆"的一个来源**；第一次生成人物关系用"**子代理两步法**"。
5. **README 只声明插件已经做的事**；工作只从真实使用里的"哪里别扭"来。

### 铁律（动手前先看）
- **材料层是防剧透的根本**：每轮只投喂**本章全文 + 上一章结尾 + 按进度裁过的背景认识**。判据是「**凡是在防"读"的我们不做**（那是结构性的），**凡是在防"说"的才写进守则**」—— 因为材料层管不了"模型自己就知道"。
- **守则（`renderPolicy`）是 prompt 的稳定前缀**：只依赖 `title` 与 `webGate`，不许混进随阅读变化的值（混进去 = 前缀每章失效一次）。
- **升不升推送号**：改到发布产物（`lib/`、`docs/*.md`、`scripts`、`README`、`cordis.patch.yml`）才升；只动 `test/` 不升。
- **发布五步**：DEV 提交 → `drc-sync.ps1 -Apply`（⚠️ **单独一条命令 + `danger-full-access`**）→ CLEAN 提交 → `push main` → 打轻量 tag → `push tag` → `gh release create --latest` → **独立核实**（raw `package.json` + `releases/latest`）。⚠️ 首页「Latest」看的是 **Release 对象**，只推 tag 不建 Release 会停在上一次。
- 改完 `lib/client.js` **立刻**跑 `--test-name-pattern="样式模板"`；**注释里不要用反引号引 CSS 标识符**。
- **删除（功能 / 形状 / 可选开关）⇒ 同一个提交里把它的守卫一起删掉，并跑一次 `npm run guard:census`。**
  这条补的是一个**缺失的流程**：写入侧规矩早就有了（改行为先写守卫、先红后绿），而**删除侧从来没有对应动作** ——
  于是 `test/` 全历史累计 `+20,417 / −987` 行（删除占 **4.8%**），`lib/` 对照 **10.8%**（2026-10-02 实测）。
  三个数（**用例总数 / 接线守卫数 / 数值钉子数**）**每次发版跑一次**：它是这个仓库**唯一朝 `test/` 的审计面** ——
  `lib/` 有死代码扫描、`docs/` 有考古，而 `test/` 历来只被"跑绿"、不被"看数"。
  ⚠️ **别把"砍数字钉子"当方向**：实测 196 条数值钉子里，"钉实现内部常量表"的脆形式**命中 0 条**，14 条钉实现表的全是**承诺型**（如 `!COMPRESSIBLE_SECTIONS.includes('时间与分线')`）。
  ⚠️ **形状变了要先重估，再决定改写**：默认行为是"把那条守卫改写得更好（通常更长）"，这正是只增的机制之一 —— 与"两个可选形状各写一套专测"叠加，守卫就翻倍，而生产往往只走一条。
- **守卫要钉行为，不要钉源码文本**（2026-10-03 B 档）：`assert.ok(source.includes('h(ImportNotes, { book })'))` 这种钉子会因为**改注释、换行、重命名局部变量**而红，而真正接错线时它未必红 —— 它是浏览器半边**没有运行时测试**时的代偿（那 43 条挤在 `client.test.mjs` 便是这么长出来的）。现在有了最小 hooks 运行时（见下面「测试」），**能渲染就别切片**。⚠️ 例外：**样式与模板文本**只能文本钉。

### 章节粒度（长章两档，2026-10-03 读者拍板：阈值 **4000 → 5000**、片长 **2500 → 3500**）
主服务场景是网文（章 2~3 千字），而实体书一章两三万字。**实测**（`drc-probe-long-chapter/probe.mjs`，
只读库层、同一本书只换配置）：25,000 字/章的书取样覆盖率 **3.6%**（网文 36.2%）、每轮注入
**40,080 字**（网文 4,008）——该省的没省、该给的没给。**两档**（默认值唯一来源：
`lib/host/chapters.js` 的 `DEFAULT_LONG_CHAPTER_SPLIT`，`index.js` 与 `library.js` 各**浅拷贝**它）：
- **> 5000 字** ⇒ 导入 / 重切分时切成**子章**（`章节名02/03…`，目标 3500 字/片）。
  **切点换行优先，换行不够（放不下想要的片数）时用句末标点补齐** —— 两者都不违反"不硬切"。
  下游一切机制自动按子章粒度工作 —— **全仓的"章号" = 章节数组位置 + 1**，不是书里印的回目。
- **≤ 5000 字** ⇒ 原样保留（v1.25 红线：短章整章装得下）。
⚠️ **阈值只决定"切不切"，每片多大由 `targetChars`（3500）决定。** 所以抬阈值**不会**让长章书
少切：2.4 万字的章在 4000 / 5000 下都 > 阈值 ⇒ **片数一样**。"想少切、章更大"要动的是
`targetChars`。
⭐ **两个旋钮一起看，因为每轮注入的上界 ≈ `max(阈值, 片长)`**。实测《神雕侠侣》（43 章 / 102 万字）：

| 阈值 | 片长 | 章数 | 每轮注入上界 |
|---|---|---|---|
| 不切 | — | 43 | 33,958 字 |
| 5000 | 2500 | 427 | 4,557 字 |
| **5000** | **3500** | **312** | **4,557 字** |
| 5000 | 4000 | 276 | 4,557 字 |
| 5000 | 5000 | 224 | 5,141 字 |

那个 4,557 字的最大章是**≤ 5000 所以没被切**的整章 ⇒ 只要片长不超过它，合并碎片就是**免费**的
（427 → 312 条目录，每轮一个字没多付）。`> 4557` 才开始顶到上界。
⚠️ **停在 3500 而不是 4000（4000 的章数更少）是为可测性付的价**：4000 会让测试夹具的"3 片"
窗口（长度 > 8000）与它的证伪条件（长度 < 8000，阈值调回 8000 就该保完整）互斥。
⚠️ **改阈值/片长都不追溯**：已导入的书不自动重切（章号是读者的进度锚点），要吃新粒度
必须走 `reindex-books.mjs`。
⚠️ **中间那一档（4000–8000 保完整、取样侧按比例读厚）已于 2026-10-03 连同机制一起删除**：
阈值降到 4000 之后它不再存在。⚠️ **这不是"删了段死代码"** —— 在 6000 的阈值下那一档是活的
（删它会让 4000–6000 的章在背景取样里少读 0%–33%）；只有在 4000 下才真的没人用它。
⚠️ **阈值后来抬到 5000 不会让那套机制回来**：4000–5000 的章确实又保完整了，但"保完整"是
"没超过阈值所以不切"，**不是**"按比例读厚"——两者是不同的东西，后者已删且没有回来的理由。
唯一残余是**既没换行也没句末标点**的非散文章：保持整章、和短章拿同一份额度，并如实报
`no-break-point`（那不是漏了一档，是那种文本本来就没有可落切点的地方）。
⚠️ **已导入的书不会自动重切**：章号是进度锚点 ⇒ 就地重切只走 `library.reindex()`
（`scripts/reindex-books.mjs`）。它按字符位置把进度/笔记/草稿/覆盖**精确搬家**；
**讨论时间线**与对不上号的笔记仍**拒绝落盘**（没有片内偏移，猜一个章号比拒绝更糟）。
⚠️ 切分过的书里，跳读闸 / 「只记最近这一段」的"章数"按**子章**计（50 片 ≈ 5 个书章）；
进度与面板上的章号也是子章号（标题里仍带着书自己的回目，如 `第8章 风雪03`）。

### 格式版本（schema 声明，2026-10-03 A3）
`background.md` / `notes.md` 的头部注释与 `drafts.json` 的顶层字段都声明着自己的格式版本（`*_SCHEMA_VERSION`）。
⚠️ 从前这些常量**只写不读**，真正会咬人的场景是**降级**：读者先用新版本插件（写下新格式），再回退到本版本；
本版本的解析器把不认识的部分当 `unknown` 或直接忽略，然后**照常写回** —— 新格式的内容被永久抹掉，
而文件是读者自己的理解与摘抄，没有第二次机会。
现在**声明了就必须校验**：声明的版本**比我们新** ⇒ 拒绝覆盖 / 改写，抛 `*_SCHEMA_UNSUPPORTED`
（**409，不是 400**：当前状态不允许写，不是请求写错了），消息里说清"声明的是哪个版本、我们认识到哪个、文件原样未动"。
声明**等于 / 更旧 / 干脆没声明**（老文件、导出副本）一律**照常写** —— 升级路径不许被自己挡住。
⚠️ 只拦**会改既有字节**的那几步：`writeBackground`、`remapNoteCoordinates`、草稿的写（`upsertDraft` / `deleteDraft`）。
`notes.md` 的**追加**（`appendNote` / `appendTrashMarker`）**刻意不拦** —— 追加不可能丢数据，而拦住它等于
"降级之后连笔记都记不了"，比它要防的事更糟。守卫：`test/schema-guard.test.mjs`。

### 有意为之 / 别误修
- 目录里的「**卷**」**不**持久化；**书架分类**（存"收起的"）与**人物卡**（存"展开的"、默认全折叠）持久化 —— **语义相反是刻意的**，各有守卫。
- **「补齐」只由三处触发**（面板按钮 / 发笔记 / 跳读闸），**聊天不触发** —— 有意：花钱的动作不由模型决定。
- **`block-all` / `block-book` / `off` 三档的提示词各不相同**（代价：在两档之间切换会让守则前缀失效一次，是有意的取舍）。
- README「安装」把 `dsh-better-sidebar` 写成前置，而代码零引用（读者："前置先不管就这样写"）。
- **契约测试里 `/context` 那条断言是有意删掉的**（面板入口摘了，路由保留），不是漏网。

### 背景认识的两族（**加新节之前先读这段**）
`background.md` 是 AI 对这本书的理解，但它**不全是给 AI 看的** —— 现在**三族**：
- **⓪ 元判断族（永远整条注入、不参与权重与保底）**：**「文本类型」**（2026-10-02 建）—— 第一批由子代理写**一句话的形态**（**200 字以内**）：
  属于什么类型（武侠？有没有 cp？男频还是女频？不是小说就说它是什么书）、**第几人称**、**写作方式**、**主角是谁**，
  **再给各条目一点侧重**（人物 / 世界观 / 分线各自该重在哪儿 —— 这是给后面几节定写法）。
  ⚠️ **剧情只用省略号带过**（"本书讲了主角穿越到 xxx 这样的一个世界后……"）、**不对故事走向与内容下判断** ——
  读者 2026-10-03 要求**模糊的是剧情**，并把"不许推断后续"从**提示词**改成**机制**承担。
  ⚠️ ⚠️ **"给各条目一点侧重"那半句不许删**（2026-10-03 读者当场更正）：他给的省略号示例只是在说"一句模糊的作品简介该长什么样"，
  从没说这一节不该指导后面几节怎么写；而它**每批都注入**，删掉侧重就等于让后面几节失去写法依据。
  ⚠️ **它不是范围限制**（不写"只记哪几个人"这类范围 / 数量上限）——
  2026-10-02 实测过：第一版我写的是"人物卡**收到什么程度**"，模型立刻把它变成了名单上限（"只记竹纤、练霓裳、凌慕华三人"）。
  ⚠️ **每一批都注入**（它是"条目该怎么写"的依据）；⚠️ 它**不进权重表** —— 按权重分的话它先拿保底再被裁，**恰好砍掉最关键那句**。
  ⚠️ **2026-10-03：曾放宽为「可重判」，当天又收回 —— 现行就是「只写一次 + 每批注入」**。
  放宽的理由是"判错就会一路错下去，而'写一次'没有纠错口"；收回的理由是**稳定性**（读者原话）：
  它是**每批都注入的方向指导**，一改，后面所有批次的写法方向跟着变 —— 而"改"这个动作本身
  （哪怕改对了）也会让已经写下的条目与新方向不一致。⇒ **宁可一开始写得模糊，也不要中途转向。**
  ⇒ 误判风险**由模糊化的简介承担**（见上面两条），**不设自动纠错口**；模型每批看到的是同一句判断。
  ⇒ 机制上它就在 `BACKGROUND_WRITE_ONCE_SECTIONS` 里（已有内容 ⇒ 模型新写的整条丢弃、不留归档）。
  ⚠️ **2026-10-03（当天第二次修）：`#drc-update` 点名 `取代:` 这一节不再清空它，改成"换手"。**
  收回重判时暴露出一个老洞：它在只写一次里时，一条 `节: 文本类型` + `事实: <新判断>` +
  `取代: <旧判断>` 的更正会**先把新判断丢掉、再由取代循环把旧判断搬走** ⇒ 指南针**整个清空**
  —— 而它是**每批都注入**的方向指导，空掉之后后面每一批都没有方向；重判收回后这还是**唯一**
  的纠正渠道。现行规则：**只有调用方显式点名 `取代:` 时才允许换手**（新判断顶掉旧的、
  旧判断**原文**搬进「已取代」，与「人物状态」替换分支同一套语义与同一个归档格式）。
  ⚠️ **这与被收回的"可重判"不是一回事**，别混：可重判是**模型每批自己申请**重写（额外一次
  子代理调用、方向会漂）；这个例外是**调用方**点名才生效 —— **零额外调用**，而且"模型自己写的
  重复内容一律丢弃"一个字都没变。把同一句话写回来 ⇒ **零动作**（不留归档）。
  守卫：`test/background-entities.test.mjs`「「只写一次」的例外：调用方**显式点名取代**时换手」，
  三段分别钉"新判断落地 / 同一句话写回来原样保留 / 没点名照样丢弃"，两处各有变异证据。
  ⚠️ 我们**不提供**类型清单／类型表（判断靠模型读前文）；**宽松、大概就行**，别写成长篇分析，也别写死。
- **① 给模型的（按权重 + 每节保底）**：`人物关系 / 人物 / 世界观 / 前文脉络 / 文风（只写一次）`（`通用概念` 是兜底，非小说常为空；**武功 / 功法 / 招式 / 器物 / 势力 / 规矩这类"设定"归「世界观」**，别往兜底里塞）。
  ⚠️ **「人物关系」的结构（2026-10-02 定稿）**：**一条写一对人、两个视角一次写全** —— `- 甲 ↔ 乙：什么关系、怎么变的`；
  同一对人**按阶段可以多条**（旧文件里 `竹纤 ↔ 练霓裳` 就有第5-29章与第33-49章两条，那是"关系史"的自然形态）。
  **一条 80 字内**；**只写关系、不写经历**（经历在「人物」里）。
  ⚠️ 中途试过一版"按有卡的人分组 + 两侧各写一条"，读者实测后**否掉了**：25 字上限 + 分侧把关系压成标签（22 字/条 vs 旧版 82 字/条），他说"不如之前的版本"。
  ⚠️ **「人物」= 一条说一件事**（每条以 `` `第N章` `` 开头、按时间排，一条 40 字内）；有新信息就**追加一条**。
  ⚠️ 2026-10-02 曾试过"段落式小传"（一段 = 一个条目、段内多句），**读者实测后改回"条"**（"重复的问题我们已经处理完了，段和条的形式问题……还是用条比较好"）—— **条更细**：超预算时能逐条丢，也不会在压缩时被合成巨段（实测出过 715 字一条）。
  ⚠️ **立卡门槛 = 两问**：① 有没有**只关于他自己**的事实？② 够**两条**吗？两条都过才立卡；过不去的把名字与事实写在关系条目里（`甲 ↔ 穆山：…`），**攒够两条再立卡**（"现在不立卡"不等于"永远不立"）。
  ⚠️ **分工判据（两条，都写进规则 17）**：
  ① 治"关系与人物重复"：「**把主语换成别人，这条还成立吗？**」—— 换成"他与某人的关系"还成立 ⇒ 那是关系，只写关系条目；人物段落里不重复。
  ② 治"人物与前文脉络重复"（2026-10-02 加）：「**这条能挂到某一个人名下吗？**」—— 能 ⇒ 写人物；不能、或要横跨几个人 ⇒ 写前文脉络。
  ⭐ **三节各管一件事**：**人物 = 人 · 前文脉络 = 时间线（含"没有归属人的事"）· 时间与分线 = 骨架/结构**（后者只给读者看）。
  ⚠️ **「前文脉络」必须独立存在**（读者问过"段落式之后还要不要它"）—— 它扛着三件人物卡做不到的事：① **没有归属人的事件**（势力更替 / 战事 / 群体事件）没地方放；② 它是**唯一"按时间查"的正交索引**；③ 引擎挂在它身上：**扁平节才有逐条裁剪**（超预算丢最旧的）、按区间合并最便宜、以及规则 7 的"**按章号区间防重**"。实测它和人物条目只重合 4–15% ⇒ 只要分工明确就不重复。
  ⚠️ ⚠️ **别按"文本里有没有这个名字"数关系**（`relationsOf` 的教训）：要按**归属**数（`### 甲` 下的每一条都属于甲）。
  ⚠️ **补齐子代理每批只看到这五节**：`FILL_INCREMENTAL_SECTIONS = ['文本类型','人物状态','人物关系','人物','世界观']`（**逐字有测试钉住**；⚠️ 2026-10-03 更正：这里原先写的是 `[…,'前文脉络']`，**与实际常量不符** —— 漏了「人物状态」、多了那个已并入的旧节。文档是没人审计的那一面，这类漂移只能靠"顺手核对"抓）——
  **「文风（只写一次）」写一次、之后补齐侧不再注入**（稳定特征，重读没有新信息）；**「文本类型」每批都注入、但只写一次**（写法依据 —— 见上面 ⓪ 那条；2026-10-03 当天曾放宽为"可重判"，当天收回）。两者的区别就在这里。
  ⚠️ 这里的"不注入"指**补齐子代理的上下文**；`文风` 仍在**陪读对话**的注入族里（给 AI 定口吻）。
  ⚠️ **一批的输出有预算了**（2026-10-03，**事前**而不是事后）：`memory.js` 的 `MEMORY_ENTRY_BUDGET = 48` 条 / `MEMORY_CHAR_BUDGET = 4000` 字，写进**规则 5**（在固定块内、跨批逐字相同 ⇒ 不破前缀缓存）。取值理由：正常批实测 2–4 千字，4000 是**上界**；宿主单次输出 32768 token ≈ 12,600 字，留 2/3 余量；48 = 4000 ÷ 83（规则 5 自己的尺子"40–80 字/条"）。超了 `fill()` 用 `memoryBudgetOverrun` **如实 warn 一笔、照样落盘**（背景认识只增不减，删内容比超预算糟得多）。
  ⚠️ 那两个常量是**估计值、没有真机标定**；读者若觉得记忆变薄，改这两个数即可。
- **② 给读者的（存盘 / 导出 / 面板可见，永不注入）**：`已取代`（归档，先例已有）、**`时间与分线`**（2026-10-01 建好）、**`冷档案`**（2026-10-02 建，代码侧的冷归档区 —— 见 v2.22）。
  ⚠️ 曾经并列的「**伏笔与未解**」已按读者要求**并进「时间与分线」**、不再单独成节（写在条目里标 `【伏笔】` 即可）—— 别再把它当成一个现行分区。
  ⭐ **「时间与分线」也有天花板了**（2026-10-03）：它从前是**唯一**既不注入、又不压缩、又不归档的节（`planArchive` 的循环**只遍历注入族**）⇒ 只增不减、**无上限**，而它偏偏是读者要看的"骨架 + 支线"。现在 **`主线`（骨架）永不归档**（搬走它等于把读者看这一节的目的搬走）、**`支线`单元整条出窗口才搬**进冷档案（`BACKGROUND_BACKBONE_UNITS` 是"永不搬"的唯一清单）。判据：单元的**最新章号**出活跃窗口，且**整条才搬** —— 搬一半会让读者看到"这件事说了一半"。⚠️ 这条**配套**轻量版写法（规则 12：阶段判据 = "这一段告一段落"、支线**可选**），否则感情线 / 单线作品整节一直空着。
  机制：`BACKGROUND_INJECTED_SECTIONS`（注入的**五**节）vs **`BACKGROUND_SECTIONS`（文件里真实存在的十节 = 元判断 1「文本类型」+ 元判断 1「人物状态」+ 注入 5 + 读者 2 + 已并入的旧节 1）** —— ⚠️ **文件级操作（解析 / 合并 / 取代 / 重写 / 建空档）一律用后者**，只有**注入**与"读者纠正"白名单用前者。**压缩是整份重写文件 ⇒ 它的提示词必须列出全部节**（含元判断与读者族），否则一压缩就永久丢掉 ✗。
  ⭐ **这些常量全部从 `lib/host/sections.js` 的 `BACKGROUND_SECTIONS_TABLE` 派生**（2026-10-03 注册表化）：**一行 = 一节**，文件节序 = 表内顺序。⚠️ 加新节**只改那张表**，别在别处再写平行表；`background.js` 只 import + re-export（消费者零改动）。接线守卫：`contract.test.mjs`「分区常量只在 host/sections.js 里定义」。
  ⚠️ ~~`BACKGROUND_ARCHIVE_SECTION` 的定义必须排在读者族常量之前（`const` 不提升）~~ —— **这条约束已经不存在**（2026-10-03）：注册表是对象字面量，没有"定义先后"这回事。
  ⚠️ **判「这一节是不是按 `### 主体` 分组的」只有一处定义：`isGroupedSection()`**（`sections.js`，判据 = 注册表那一行的 `grouped` 字段）。这个判定曾经散在 6 处 `BACKGROUND_GROUPED_SECTIONS.includes(...)`，于是加读者族时 `BACKGROUND_SECTIONS` 接对了、分组判定漏了一族 ⇒ `### 主线` / `### 【支线】… · 第N-M章` 在**每一次写盘**被静默丢掉（连带标题里的章号区间），而 627 条守卫全绿放行。行为那一半由 `background.test.mjs` 的往返断言看着，接线那一半由 `contract.test.mjs` 的守卫看着（⚠️ 那条守卫钉的是**数量**"正好一处实现"，不钉位置 —— 位置再搬一次不该红）。
⭐ **判据**：⓪ 族 = "后面几节该怎么写"的指南针；①族 = 陪读当下要用的事实（这个人是谁 / 这是什么规矩 / 我们聊到哪了 / 他怎么写的）；②族 = 你自己看与学写作用的整理。拿不准时问一句：**"这句话会不会让模型顺着说？"** —— 会，就进 ②。
⚠️ 两条硬约束：**别再往 ① 加节**（每节保底会被摊薄；唯一的合法例外是 ⓪ 族那种"不参与权重"的元判断）；**②族 AI 永远读不到** ⇒ 里面的错 / 重复**不会被 AI 自然纠正**，更依赖读者自己维护（所以它更适合写完整、更像给人看的整理）。
⚠️ ②族的节也要走**同一套增量与去重**（照旧带 `第N章` 锚点），别另起一套机制。

### ⚠️ 两步法（「人物关系」不许抢跑）
背景补齐是**两步**：① 先整理 `人物 / 世界观 / 文风 / 前文脉络 / 通用概念` 五节的**新内容**；② **再回头读「人物」**（含读者已有的认识），据此长出「**人物关系**」。
**读者 2026-10-01 明确要求保留这个顺序**（"不要直接输出人物关系，而是先总结其他内容"）⇒ 第①步里**不许**写「人物关系」。改它之前先读 `memory.js` 里 v1.66 那两段注释（记着踩过的坑与试过又撤掉的两条）。

### 已裁定不做（别再提）
EPUB 导入 · AI 页边批注（「AI 回应」就是那个通道）· "查看前文" · ①b 精确重定位 · ③ 章号锚点 · ④ 读区间工具 · ⑥ 断句 · 导入区文件选择 / 拖放 · **面板里的「AI 视角预览」**（`/context` 路由保留作只读复核）· **封存观察（sealed）** · **写一个 skill**（判据见设计记录 `skill-vs-plugin-decision.md` —— ⚠️ 该文件**不随包发布**，它不在本仓库里，只在工作区根目录）· **人设默认稿**（保持空白，只留 placeholder 例文）· **历代合并**（把压缩副本互相去重求并集 —— 交给读者自己，理由见封存件 v1.36 §279）。

### 测试
`node --test --test-isolation=none --test-concurrency=1`。守卫分三类：**纯函数单测**、**端到端注入断言**（防剧透回归）、**行为断言**（真渲染一次，钉住"点了会怎样 / 树上有什么"）。
⭐ **2026-10-03 B 档收口**：`client.test.mjs` 里**已零条**"读源码再断言"的脆钉子（**38 → 0**）；整个 `test/` 只剩 **11 条脆的**（配置契约、宿主路由表、计数普查这些**转不成行为**的），外加 3 条"读源码是为了执行"的健康守卫。
⚠️ **普查必须把"脆"与"健康"分开报**（同日修的缺陷）：原先只印一个数并标成"只增的主要来源"，而那 51 里其实有 2 条是健康的 —— 混报会让读者把健康守卫也算成代偿。判据见 `guard-classify.mjs` 的 `classifyBlock()`。

⚠️ **能跑的就别读源码**（2026-10-03 B 档）：浏览器半边有一台**最小 hooks 运行时** —— `test/helpers/hooks-runtime.mjs`（状态真的更新并重渲染、effect 真的跑、`memo` 真的浅比较、ref 真的挂、按钮真的点得动）+ `test/helpers/client-loader.mjs`（doc/react 替身与 factory 物化）。于是"组件写了但没挂上 / 回调漏接 / 渲染顺序不对 / effect 依赖漏了"这类失效模式要**渲染一次来钉**（范式见 `test/client-runtime.test.mjs`），不要退回去断言源码里出现过某一行。
⚠️ **例外是"钉文本本身"的两类**：① `样式与模板：` —— 那段 CSS 长什么样、模板字符串里不许出现反引号，运行时替身没有 DOM / 排版引擎，搬过去只会把断言变弱；② `文本契约：` —— 钉的是**看不见的契约**：反向禁令（"不许再用浏览器原生确认框"）、宿主路由表（"预览摘了但 `/books/:bookId/context` 路由保留"）、**计数不变式**（"进笔记页的入口数 == 记账处数"，防的是**将来**新增入口忘了记账）、以及"第一帧闪一下"这类**运行时看不到中间帧**的接线。**两类都以名字前缀标注**，普查把它们合成"文本钉子"一类（不计入脆的"接线守卫"）。
⚠️ **理由注释钉子能转就转**：`文本契约：` 一度用来钉"卷的开合是过程状态、分类的收起是偏好，别统一掉"这类**理由文字** —— 2026-10-03 已把它转成行为（展开一卷 ⇒ 持久层一个键都没写 + 新会话初始态与第一次逐项相同，写/读两个变异各红一条）。**留下的是"转不了"的，不是"懒得转"的。**

⭐ **"读源码再断言"的用例分四类**，判据的**唯一来源**是 `scripts/guard-classify.mjs`（`classifyBlock()`）：
| 类 | 判据 | 处置 |
|---|---|---|
| **行为** | 不读生产源码 | 正常 |
| **文本钉子** | 读源码 + 名字以 `样式与模板：` 或 `文本契约：` 开头 | **该留**（钉的就是文本） |
| **接线守卫** | 读源码 + 做**文本/位置/计数**断言 | **要转**（能渲染就渲染） |
| **接线守卫（为了执行）** | 读源码是为了**把源码跑起来**（迷你渲染器、模块契约） | 健康 |

⚠️ **位置 / 计数钉子也是字符串钉子**（2026-10-03 修正）：`const at = source.indexOf('…')` 再 `assert.ok(at > 0)` 这种形状**不是** `assert.match`，普查原先把它判成"为了执行" ⇒ **把脆钉子数少了 3 条**（`交接：清空是显式的…`、`交接：\`wait\` 必须在清空之前返回…`、`竞态守卫：每个按书加载的资源各自装了守卫`）。判据现在**宁可宽**：读源码取位置/切片来断言，就是在钉文本。

⚠️ **防复发靠元守卫**：`test/guard-discipline.test.mjs` 断言「`client.test.mjs` 里读生产源码的用例，不许再是字符串比对」—— 它 import 的**就是上面那份判据**（复制一份到测试里就是本仓库反复栽的"同一概念多份定义"）。它自己读的是 `test/` 下的文件，所以**不会**被普查算成接线守卫。
