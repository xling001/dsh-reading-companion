## 现行约定

### 定位（所有取舍都要服从它）
1. **尽可能用 DSH 现成的功能与工具**（能宿主侧现算的，就不让客户端上报）。
2. **主服务场景：中长篇小说。**（⚠️ 这是**投入排序**，**不是给模型的指令** —— 每条提示词都必须对**任何文本**成立：读文献的人不该在提示词里看到一句"小说优先"。读者 2026-10-02 纠正过一次，见修订史 §569。）
3. **导出文件的质量（`notes.md` / `background.md`）是价值主轴。**
4. **背景文件是"记忆"的一个来源**；第一次生成人物关系用"**子代理两步法**"。
5. **README 只声明插件已经做的事**；工作只从真实使用里的"哪里别扭"来。

### 铁律（动手前先看）
- **材料层是防剧透的根本**：每轮只投喂**本章全文 + 上一章结尾 + 按进度裁过的背景认识**。判据是「**凡是在防"读"的我们不做**（那是结构性的），**凡是在防"说"的才写进守则**」—— 因为材料层管不了"模型自己就知道"。
- **守则（`renderPolicy`）是 prompt 的稳定前缀**：只依赖 `title` 与 `webGate`，不许混进随阅读变化的值（混进去 = 前缀每章失效一次）。
- **升不升推送号**：改到发布产物（`lib/`、`docs/*.md`、`scripts`、`README`、`cordis.patch.yml`）才升；只动 `test/` 不升。
- **发布五步**：DEV 提交 → `drc-sync.ps1 -Apply`（⚠️ **单独一条命令 + `danger-full-access`**）→ CLEAN 提交 → `push main` → 打轻量 tag → `push tag` → `gh release create --latest` → **独立核实**（raw `package.json` + `releases/latest`）。⚠️ 首页「Latest」看的是 **Release 对象**，只推 tag 不建 Release 会停在上一次。
- 改完 `lib/client.js` **立刻**跑 `--test-name-pattern="样式模板"`；**注释里不要用反引号引 CSS 标识符**。

### 有意为之 / 别误修
- 目录里的「**卷**」**不**持久化；**书架分类**（存"收起的"）与**人物卡**（存"展开的"、默认全折叠）持久化 —— **语义相反是刻意的**，各有守卫。
- **「补齐」只由三处触发**（面板按钮 / 发笔记 / 跳读闸），**聊天不触发** —— 有意：花钱的动作不由模型决定。
- **`block-all` / `block-book` / `off` 三档的提示词各不相同**（代价：在两档之间切换会让守则前缀失效一次，是有意的取舍）。
- README「安装」把 `dsh-better-sidebar` 写成前置，而代码零引用（读者："前置先不管就这样写"）。
- **契约测试里 `/context` 那条断言是有意删掉的**（面板入口摘了，路由保留），不是漏网。

### 背景认识的两族（**加新节之前先读这段**）
`background.md` 是 AI 对这本书的理解，但它**不全是给 AI 看的** —— 现在**三族**：
- **⓪ 元判断族（永远整条注入、不参与权重与保底）**：**「文本类型」**（2026-10-02 建）—— 第一批由子代理写一句
  **自己的简介**（**200 字以内**）：什么方向、讲的是谁的故事、**人称与视角**（限知？群像？）、有没有**第二位主角**，
  再给**各条目一点侧重**（人物 / 世界观 / 分线各自该重在哪儿）。
  ⚠️ **它不是范围限制**（不写"只记哪几个人"这类范围 / 数量上限）、**也不推断后续**（"后面就是他们三人闯荡江湖"这种推论不许写）——
  2026-10-02 实测过：第一版我写的是"人物卡**收到什么程度**"，模型立刻把它变成了名单上限（"只记竹纤、练霓裳、凌慕华三人"）。
  ⚠️ **写一次、之后每一批都注入**（它是"条目该怎么写"的依据）；⚠️ 它**不进权重表** —— 按权重分的话它先拿保底再被裁，**恰好砍掉最关键那句**。
  ⚠️ 我们**不提供**类型清单／类型表（判断靠模型读前文）；**宽松、大概就行**，别写成长篇分析，也别写死。
- **① 给模型的（按权重 + 每节保底）**：`人物关系 / 人物 / 世界观 / 前文脉络 / 文风（只写一次）`（`通用概念` 是兜底，非小说常为空；**武功 / 功法 / 招式 / 器物 / 势力 / 规矩这类"设定"归「世界观」**，别往兜底里塞）。
  ⚠️ **「人物关系」的结构（2026-10-02 定稿）**：**一条写一对人、两个视角一次写全** —— `- 甲 ↔ 乙：什么关系、怎么变的`；
  同一对人**按阶段可以多条**（旧文件里 `竹纤 ↔ 练霓裳` 就有第5-29章与第33-49章两条，那是"关系史"的自然形态）。
  **一条 80 字内**；**只写关系、不写经历**（经历在「人物」里）。
  ⚠️ 中途试过一版"按有卡的人分组 + 两侧各写一条"，读者实测后**否掉了**：25 字上限 + 分侧把关系压成标签（22 字/条 vs 旧版 82 字/条），他说"不如之前的版本"。
  ⚠️ **「人物」= 一条说一件事**（每条以 `` `第N章` `` 开头、按时间排，一条 40 字内）；有新信息就**追加一条**。
  ⚠️ 2026-10-02 曾试过"段落式小传"（一段 = 一个条目、段内多句），**读者实测后改回"条"**（"重复的问题我们已经处理完了，段和条的形式问题……还是用条比较好"）—— **条更细**：超预算时能逐条丢，也不会在压缩时被合成巨段（实测出过 715 字一条）。
  ⚠️ **立卡门槛 = 两问**：① 有没有**只关于他自己**的事实？② 够**两条**吗？两条都过才立卡；过不去的把名字与事实写在关系条目里（`甲 ↔ 穆山：…`），**攒够两条再立卡**（"现在不立卡"不等于"永远不立"）。
  ⚠️ **分工判据（两条，都写进规则 17）**：
  ① 治"关系与人物重复"：「**把主语换成别人，这条还成立吗？**」—— 换成"他与某人的关系"还成立 ⇒ 那是关系，只写关系条目；人物段落里不重复。
  ② 治"人物与前文脉络重复"（2026-10-02 加）：「**这条能挂到某一个人名下吗？**」—— 能 ⇒ 写人物；不能、或要横跨几个人 ⇒ 写前文脉络。
  ⭐ **三节各管一件事**：**人物 = 人 · 前文脉络 = 时间线（含"没有归属人的事"）· 时间与分线 = 骨架/结构**（后者只给读者看）。
  ⚠️ **「前文脉络」必须独立存在**（读者问过"段落式之后还要不要它"）—— 它扛着三件人物卡做不到的事：① **没有归属人的事件**（势力更替 / 战事 / 群体事件）没地方放；② 它是**唯一"按时间查"的正交索引**；③ 引擎挂在它身上：**扁平节才有逐条裁剪**（超预算丢最旧的）、按区间合并最便宜、以及规则 7 的"**按章号区间防重**"。实测它和人物条目只重合 4–15% ⇒ 只要分工明确就不重复。
  ⚠️ ⚠️ **别按"文本里有没有这个名字"数关系**（`relationsOf` 的教训）：要按**归属**数（`### 甲` 下的每一条都属于甲）。
  ⚠️ **补齐子代理每批只看到这五节**：`FILL_INCREMENTAL_SECTIONS = ['文本类型','人物关系','人物','世界观','前文脉络']`（**逐字有测试钉住**）——
  **「文风（只写一次）」写一次、之后补齐侧不再注入**（稳定特征，重读没有新信息）；**「文本类型」写一次但每批都注入**（写法依据）。两者的区别就在这里。
  ⚠️ 这里的"不注入"指**补齐子代理的上下文**；`文风` 仍在**陪读对话**的注入族里（给 AI 定口吻）。
- **② 给读者的（存盘 / 导出 / 面板可见，永不注入）**：`已取代`（归档，先例已有）、**`时间与分线`**（2026-10-01 建好）、**`冷档案`**（2026-10-02 建，代码侧的冷归档区 —— 见 v2.22）。
  ⚠️ 曾经并列的「**伏笔与未解**」已按读者要求**并进「时间与分线」**、不再单独成节（写在条目里标 `【伏笔】` 即可）—— 别再把它当成一个现行分区。
  机制：`BACKGROUND_INJECTED_SECTIONS`（注入的六节）vs **`BACKGROUND_SECTIONS`（文件里真实存在的九节 = 元判断 1 + 注入 6 + 读者 2）** —— ⚠️ **文件级操作（解析 / 合并 / 取代 / 重写 / 建空档）一律用后者**，只有**注入**与"读者纠正"白名单用前者。**压缩是整份重写文件 ⇒ 它的提示词必须列出全部节**（含元判断与读者族），否则一压缩就永久丢掉 ✗。
  ⚠️ **`BACKGROUND_ARCHIVE_SECTION` 的定义必须排在读者族常量之前**（`const` 不提升 —— 放在后面会让整份模块 `ReferenceError`、全部测试一起红）。
  ⚠️ **判「这一节是不是按 `### 主体` 分组的」只有一处定义：`isGroupedSection()`**（`background.js`）。这个判定曾经散在 6 处 `BACKGROUND_GROUPED_SECTIONS.includes(...)`，于是加读者族时 `BACKGROUND_SECTIONS` 接对了、分组判定漏了一族 ⇒ `### 主线` / `### 【支线】… · 第N-M章` 在**每一次写盘**被静默丢掉（连带标题里的章号区间），而 627 条守卫全绿放行。行为那一半由 `background.test.mjs` 的往返断言看着，接线那一半由 `contract.test.mjs` 的守卫看着。
⭐ **判据**：⓪ 族 = "后面几节该怎么写"的指南针；①族 = 陪读当下要用的事实（这个人是谁 / 这是什么规矩 / 我们聊到哪了 / 他怎么写的）；②族 = 你自己看与学写作用的整理。拿不准时问一句：**"这句话会不会让模型顺着说？"** —— 会，就进 ②。
⚠️ 两条硬约束：**别再往 ① 加节**（每节保底会被摊薄；唯一的合法例外是 ⓪ 族那种"不参与权重"的元判断）；**②族 AI 永远读不到** ⇒ 里面的错 / 重复**不会被 AI 自然纠正**，更依赖读者自己维护（所以它更适合写完整、更像给人看的整理）。
⚠️ ②族的节也要走**同一套增量与去重**（照旧带 `第N章` 锚点），别另起一套机制。

### ⚠️ 两步法（「人物关系」不许抢跑）
背景补齐是**两步**：① 先整理 `人物 / 世界观 / 文风 / 前文脉络 / 通用概念` 五节的**新内容**；② **再回头读「人物」**（含读者已有的认识），据此长出「**人物关系**」。
**读者 2026-10-01 明确要求保留这个顺序**（"不要直接输出人物关系，而是先总结其他内容"）⇒ 第①步里**不许**写「人物关系」。改它之前先读 `memory.js` 里 v1.66 那两段注释（记着踩过的坑与试过又撤掉的两条）。

## 修订史（新在前）
> **v3.0 修订（记忆系统重构第一刀：冷归档接进触发链 —— 先归档、后压缩）**
>
> 596. **读者定调**："我们现在重新搞记忆系统，所以版本是 **3.0** 了。" ⇒ 3.0 = 把记忆的维护**从模型手里收回代码**，分三刀：
>       · **① 冷归档进链**（本轮 ✓）：补齐前先跑**纯代码**的冷归档（把整条落在活跃窗口之外的旧条目搬进 `## 冷档案`），**能靠归档降下来就不叫模型压缩**；
>       · ② **注入改成视图投影**（注入 = 骨架 + 活跃窗口 + 每主体最新状态，代码切片算出来）；
>       · ③ **实体状态快照**（每主体保留"当前状态（可覆盖）+ 最近几条"，读者已同意，前提是备份机制 —— v2.22 已就位）。
>       为什么非改不可：**压缩 = 叫模型把整份文件重写一遍**，而模型单次输出上限 **32768 tokens**（≈2.6 tokens/字）⇒ 文件 1.2–1.5 万字就压不出完整输出（实测撞顶，还出现过"响应 0 字"的白跑）。**这不是"百万字"的问题，是 ~85–100 章的问题。**
>
> 597. **本轮实现（接线的三处，缺一个就静默失效）**：
>       · **补齐路由**：在算缺口**之前**插入冷归档（`applyArchive` + `library.backgroundArchive`，复用压缩那套 **CAS 比对 + 整份备份**），成功后写一份**增量记录**（`background.history/NNNN-…-归档.md`），再重新读文件、才去判断"是否仍然超预算"。
>         ⚠️ **归档发生在缺口判断之前** ⇒ **"没有缺口、这一趟 skipped"时也会归档**（归档是代码做的，与有没有缺口无关）—— 有守卫钉着。
>       · **返回链**：fill 结果里加 `archived`；⚠️ 路由层是**逐字段**挑给前端的，**只加在 fill 结果上不算数**（第一版就漏在这里，测试报"响应里没有 archived"）。
>       · **客户端**：补齐那句提示要加"另有 N 条更早的记忆已归档（不再进上下文；原文仍在「冷档案」里）"—— 条目"不进上下文"是看不见的变化，不说清楚读者只会以为 **AI 突然忘事了**。
>       · **配置**：`archiveWindowChapters: 120`（`cordis.patch.yml` 与 `CONFIG_DEFAULTS` 同值，逐键守卫比对）；**0 = 关掉冷归档**（退回"只靠压缩"的旧行为）。
>       · ⚠️ **踩到一个 TDZ**：我最初在归档块里用了 `progressIndex`，而它在后面才 `const` 声明 ⇒ **整条补齐路由抛错**（几十条路由用例一起红）。改成"就地按同一口径取进度"（面板给的 `atChapter` 优先，否则读落盘进度）。
>
> 598. **本版验证：668 / 668 / 0 / 0**（新增守卫：**"归档是纯代码的，不该叫模型压缩"** —— 断言 `labels` 里不出现 `:compact`，以及文件里出现 `## 冷档案`、被归档的条目原文还在、留了整份备份）。⚠️ **未发布**（`package.json` 已升到 **3.0.0**）。
