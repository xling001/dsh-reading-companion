# 背景认识（`background.md`）格式与维护

> 这份是**参考手册**，不是入门读物。想知道它是什么、为什么这样设计，先看
> [README 的「五个特色」](../README.md#五个特色) 与 [`design.md`](./design.md)。
> 这份文档从 README 里搬出来（2026-10-03）：它讲的是**格式细节与维护动作**，
> 放在 README 里会让"第一次打开"的人先读手册再读介绍。

`background.md` 是陪读 AI 对这本书的理解，一份随进度**只增不减**的 Markdown。
它在书的陪读文件夹里，**你随时可以直接打开读、也可以改** —— AI 记错了，改一行就是纠正。

## 长什么样

```markdown
## 文本类型        ← 元判断：只判"是什么类型 + 主视角是谁"（40 字内），其余一律不判
- 男频武侠无限流，主视角是孟奇，他穿越到了这个世界……
## 人物状态        ← 一人一行"此刻在哪 + 站在哪边"（≤30 字、带章号）；每批**替换**
### 甲
- `第41章` 少林后山养伤，与乙结盟。
## 人物关系      ← `###` 写关系双方；名下一条写一对人、两个视角一次写全；只写关系
### 甲 × 乙
- 同门 → 对手（`第3章` 起结怨）；`第8章` 一起拜入师门
## 人物          ← 一条说一件事（每条以章号开头、按时间排），一条 40 字内
### 甲
- `第2章` 借六岁女童之身重生，处境贫苦。
- `第29章` 潭边第一次无法再掩饰心意（`第31章` 立下要护住身边人的目标）。
## 世界观 / ## 文风（只写一次） / ## 通用概念（兜底）
## 时间与分线      ← 只给你看：不进提示词，AI 读不到
### 主线
- `第1-30章` 阶段名：一句话说清这一段是什么（阶段 = 一次大换场）。
- `第18-24章` 无归属人的大事（原「前文脉络」的职责，3.0 并入这里）。
### 【支线】单元名 · 第45-72章
- `第45章` 起：怎么开始的。 / `第61章` 转折：关键转折。 / `第72章` 收：怎么结束的。
- ⭐ 影响：留下了什么（得到或失去的东西 / 结下的关系 / 改变的立场 / 下一步指向哪里）。
（被新条目取代的旧说法会搬进末尾 `## 已取代`，保留但不再喂给 AI）
```

## 哪几节喂给 AI，哪几节不喂

判据只有一句：**「这句话会不会让模型顺着说？」**

**喂**：**文本类型**（元判断）+ **人物状态**（一位一句"此刻在哪 + 站在哪边"）+ 人物关系 / 人物 / 世界观 / **文风（只写一次）**（+ 非小说的通用概念兜底）

- ⚠️ 「**文本类型**」是**开头那节元判断**：第一次补齐时让 AI 写**一句话**，**只判两件事** —— **属于什么类型 + 主视角是谁**，**其余一律不判**（人物关系 / 感情线 / cp / 谁是女主 / 故事走向都不判：这些在开头几十章里读不出来，而它**只写一次、之后每批都带着**，判错会一路错下去）。你可以直接改它。
- ⚠️ 「**人物状态**」是**一人一行**的"现在进行时"：**只写"此刻在哪 + 站在哪边"**（≤30 字，行首带章号），**每批替换**上一批（所以它结构性不存在重复）。它只带**最近活跃的 8 位** —— 更早的人只剩「人物」里的最后一条（他最后在干嘛），那是冷归档之后本来就有的形状。**这一节是给 AI 用的**：冷归档把历史搬走之后，它是 AI 唯一能知道"这个人**现在**站在哪边"的地方。
- ⚠️ 「**人物关系**」的 `###` 写**关系双方**（`### 甲 × 乙`），名下**一条写一对人、两个视角一次写全**（`- 同门 → 对手（第3章）`），同一对人**按阶段可以多条**；**只写关系，不写经历**（经历在「人物」里）。两者的分工判据是「**把主语换成别人，这条还成立吗？**」—— 换成"他与某人的关系"还成立 ⇒ 那是关系，只写在关系里。
- ⚠️ 「**世界观**」的 `###` 写**势力 / 地名 / 设定名**（`### 少林`）。**武功 / 功法 / 招式 / 器物 / 势力 / 规矩这类"设定"都归这一节**（别往「通用概念」兜底里塞）。
- ⚠️ 「**人物**」是**一条说一件事**（每条以 `` `第N章` `` 开头、按时间排，一条 40 字内）；有新信息就**追加一条**。
- ⚠️ **立卡门槛**：① 有没有**只关于他自己**的事实 ② 够**两条**吗 —— 两条都过才开 `###`；过不去的把名字与事实写在关系条目里，等他攒够两条再立卡。
- ⚠️ 「**文风（只写一次）**」只在**第一次补齐**时写一次 —— 行文风格不随剧情变，一次提炼就够；名字里的"只写一次"就是这件事（你随时可以打开 `background.md` 自己补改它）。

**不喂**：**时间与分线**（它常常写着"这里像埋了伏笔"，喂进去等于给提示 ✗）与归档区 `已取代`。
所以「时间与分线」**只会出现在文件与导出里** —— 它是留着给你自己复盘、学结构用的。

## 「时间与分线」写成"树枝"，不是流水账

**主线**只写骨架（每条一个阶段 = 一次大换场），**每个单元**（一个副本 / 一段关系 / 一段旅程）只写"怎么进来的 / 关键转折 / 怎么出去的"，最后一条**必须是 `⭐ 影响`** —— 它对后面留下了什么。
**"这件事讲完了"就收一个单元**，同一件事跨几十章也还是一个单元（打包说完，不按章摊平）。

## 人物卡（只读视图）

面板里的「**人物**」卡只含你读到的部分，按主体归堆、标注最新章号。
**它的判定就是分区**：只有 `## 人物` 一节里的主体出卡 —— 想让某个名字进出这张列表，改 `background.md` 的归属即可。
**建卡门槛**：他得有"自己的线"（有关系网 / 有自己的经历与动机），并且写得出**只关于他自己**的一条；只是被提到过的次要角色写在主角名下就行 —— **等他有了自己的戏再建卡**（"现在不建"不等于"永远不建"）。

## 缺口：不硬补

从目录跳到很靠后的一章（缺口超过阈值）会先拦一下，让你选「这些我都读过 / 只记最近这一段 / 先不补」—— 把没读到的章节写进记忆是**不可逆**的。
而发笔记那一路**不会空手而归**：它会自动把**开头 30 章**跑完，再告诉你去面板补剩下的。

## 压缩：唯一会删内容的一步

所以要过**五条硬校验**（保名 / 保主体 / 保号 / 真的变小 / 读者族条目不许少），任何一条不过就**整批丢弃、文件一字不动**。
每次压缩前还会留**一代带时间戳的备份，一份不删**，导出时一代不漏地跟出去。

## 同一人物被写成两个 `###` 时

用工具合并：

```bash
node scripts/merge-background-subjects.mjs --file <background.md> --merge '<被并掉的名字>=<留下的名字>'
```

默认只预览，加 `--apply` 才写，写前自动备份。
**压缩不会替你合并**：它的「保主体」校验不许丢任何一个主体。

## 想要"最完整的那一版"：把历代并起来

每一代都是**完整快照**（不是增量），压缩只做删除与合并，所以**越早的那一代覆盖的章更少、但每条更细** —— "历代 + 当前"的**并集**才是最详细的那份。

但压缩后的条目没有 id、没有稳定标题，章号区间也可能被改写，**"哪条对应哪条"无法可靠判定**，所以**插件刻意不做自动合并**。推荐做法：读完之后，把陪读文件夹（或导出的那组 `-背景-压缩前-<时间戳>.md`）**交给 AI 或别的工具**合并，**并且保留原文件**。可以直接用这段话：

> 把这本书的这几份背景认识合并成一份最详细的版本。输入：`background.md`（最新，已压缩）
> 与 `background.compactbak.*.md`（压缩前）与 `background.cleanbak.*.md`（清空前）（历代压缩前快照，越早的通常越详细）。规则：
> ① 以**并集**为目标 —— 任何一代里出现过的条目都要保留；
> ② 同一主体下按**章号**对齐；同一章号有多个版本时**取更详细的那一条**；
> ③ **不要发明**输入里没有的内容，也不要按你的小说知识补充；
> ④ 两条冲突时**并存并标注**；
> ⑤ 输出到**新文件**，**一个输入文件都不要改**；
> ⑥ 最后列出：补回了多少条、多少条无法对应、哪些章号有冲突。
